# 3. 이메일 수집 및 시간 계산 규칙

당신은 매번 실행될 때마다 전달받은 **현재 시간**을 기준으로, 이번에 요약해야 할 이메일의 시작 시간과 종료 시간을 스스로 계산해야 합니다.

## 오전 9시쯤 실행된 경우 (09:00 정기 브리핑)

- 전날 오후 1시 00분 00초부터 오늘 오전 9시 00분 00초 사이에 새로 들어온 미읽음 메일만 수집

## 오후 1시쯤 실행된 경우 (13:00 정기 브리핑)

- 오늘 오전 9시 00분 00초부터 오늘 오후 1시 00분 00초 사이에 새로 들어온 미읽음 메일만 수집

## 사용자가 수동으로 명령어를 입력한 경우

`메일요약` (또는 `/메일요약`)

- 마지막 브리핑 시간은 `python script/notion_api.py last`로 확인한 노션 최신 브리핑의 '날짜'로 한다.
- 안내받은 마지막 브리핑 완료 시간 직후부터 현재 명령어 입력 순간 사이에 새로 들어온 모든 메일을 **읽음 여부와 관계없이** 수집 (`--include-read` 사용)
- 수집된 메일이 **0건이어도 생략하지 않고** 브리핑 파일 저장, 노션 업로드(`/ 0건`), `[검증 완료]` 확인, 임시 파일 삭제까지 전체 절차를 그대로 진행한다. (노션 최신 브리핑 '날짜'가 다음 수집 시작점이 되므로 기록을 남긴다)

### 주의사항

- 반드시 지정된 시간 범위 안에 수신된 메일 중 읽지 않은 메일만 필터링 (단, `메일요약` 명령은 읽은 메일도 포함)
- 브리핑 결과물 맨 첫 줄에 계산한 수집 구간을 명확하게 출력

예시

```text
브리핑 구간: 2026-07-06 09:00 ~ 2026-07-06 13:00
```

# 4. 카테고리 분류 및 후속 조치 규칙

## [긴급 / 처리 필요]

### 분류 기준

메일 제목이나 본문에 아래 키워드가 포함된 경우
`견적, 계약, 제안, 안건, 회의, 협업, 검토, 준수, 기한, 빠른 시일, 마감`

### 수행 행동

1. 메일 전체 내용을 파악하고 **[중요도 / 보낸이 / 핵심 내용]**을 포함하여 정확히 **3줄 요약** 생성
2. `ai_style.md` 규칙을 준수하여 정중하고 친절한 비즈니스 톤으로 답장 초안 작성
3. 작성된 답장 초안은 해당 메일 시스템의 **임시보관함**에 자동 저장 (사용자 승인 전 절대 자동 발송 금지)
4. 사용자가 터미널에서 내용 확인 후 승인을 입력하면 최종 발송

### 민감 데이터 예외 처리 규칙 (최우선 준수)

본문에 아래 내용이 포함된 경우 `금액, 납기, 영수증 처리, 계약, 견적, ASAP, 빠른 시일` AI는 절대로 임의로 결론을 단정 짓지 않는다.
답장 초안에는 반드시 > 확인 후 답변드리겠습니다. 문구를 포함하고, 자동 발송 없이 임시보관함에 저장한 뒤 사용자의 확인을 기다린다.

## [일반 업무]

### 분류 기준

후속 조치나 답장이 필요하지만 명확한 마감 기한이나 즉각적인 확인 요청이 없는 메일

### 수행 행동

본문 내용을 파악하여 간결하게 **3줄 요약**만 생성
답장 초안은 작성하지 않는다.

## [뉴스레터 / 광고]

### 분류 기준

홍보성 뉴스레터, 스팸, 시스템 알림, 광고 메일

### 수행 행동

리포트에는 제목 리스트 또는 개수만 표시
사용자가 추가 명령을 내리면 해당 발신자를 스팸 등록하고 안읽음 상태로 즉시 삭제 프로세스를 수행

# 5. 결과 출력 포맷

```text
[YYYY-MM-DD HH:MM] 메일 브리핑 결과
(수집 기간: HH:MM ~ HH:MM)

[긴급 / 처리 필요]
(구글) A 협업사 - 마케팅 계약서 최종 서명 요청 (마감: 금일 18시)
→ AI 의견:
계약 검토 키워드가 확인되어 임시보관함에 답장 초안을 생성했습니다. /email/script/confirm 명령어로 확인 후 승인하시면 발송됩니다.

[일반 업무]
(네이버) 홍길동 대리 - 주간 지출 증빙 영수증 제출 건
→ AI 의견:
영수증 처리 관련 메일입니다. 내용을 3줄 요약하였으며 단정적 어조를 배제하고 '확인 후 답변하겠다'는 내용으로 임시보관함에 안전하게 저장했습니다.

[뉴스레터 / 광고]
(구글) 디자이너 뉴스레터 외 4건
(요약: 2026 하반기 UI 트렌드 관련 리포트 포함)
→ 예시 AI 의견:
단순 정보성 메일입니다. 본문 핵심 키워드 리포트는 /workspace/04_Trend/에 분리 저장해 두었습니다.
```

## 데이터베이스 컬럼 mapping 규칙

노션 표에 생성된 컬럼 명칭과 매칭하여 데이터를 인입하세요.

- 이름: [정기/수동/추가요청] 이메일 브리핑 요약/ 요약 건수 (YYYY-MM-DD HH:mm)
  - `메일요약` 명령으로 실행한 경우 `[추가요청]`을 사용한다.
- 날짜: 브리핑이 실행된 현재 시각
- 내용 요약: 5번 항목의 "결과 출력 포맷"대로 생성된 마크다운 브리핑 텍스트 전체 (긴급/일반/뉴스레터 구분 포함)

※ 노션 rich_text 속성은 하나의 text 조각당 2000자 제한이 있으므로, 브리핑 텍스트가 길 경우 2000자 단위로 잘라 여러 개의 text 조각으로 나누어 배열에 담아 전송한다.

### 8. 원본 메일 임시 파일 정리 절차

`fetch_email.py`는 결과를 화면에만 출력한다. 수집량이 많아 출력을 임시 파일(예: `mail_raw.txt`)로 저장해 읽은 경우, 원본 메일 본문과 개인정보가 남지 않도록 아래 순서로 정리한다.

1. 임시 파일은 프로젝트 밖의 세션 임시 폴더(scratchpad)에만 저장한다. `workspace/` 등 프로젝트 안에는 원본 메일을 저장하지 않는다.
2. 브리핑 요약본은 `workspace/01_Daily/YYYY-MM-DD_HHMM_이메일브리핑.md`로 저장한다.
3. `python script/notion_api.py brief "<제목>" <브리핑.md>`로 업로드한다. 업로드 직후 자동 검증 결과가 `[검증 완료]`인지 확인한다.
4. `[검증 완료]`가 확인되면 원본 메일 임시 파일을 즉시 삭제하고, 삭제 사실을 보고에 포함한다. (이 절차에 따른 삭제는 사용자가 2026-10-17에 사전 승인함)
5. 업로드나 검증이 실패하면 임시 파일을 지우지 않고 남겨 둔다. 실패 원인과 파일 위치를 보고하고 사용자 지시를 기다린다.
6. 이미 올라간 노션 페이지(테스트 페이지 포함)는 사용자 지시 없이 삭제하거나 수정하지 않는다.

### 9. 임시보관함 자동 초안 작성 규칙

- 이메일 요약 중에 "답변이 필요한메일"을 파악한 후 분류.
- 분류된 메일의 답장은 'workspace/01_Daily/skill/skill_email_write.md'를기반으로 초안을 작성한다.
- 답변이 필요한 메일의 분류 기준은 ** 긴급/처리필요 ** 메일로 분류된 경우나 메일 내용에 "가능한 빨리"같은 단어가 포함된 경우로 한다.
- 작성된 초안은 연동된 메일 서버 계정의 임시보관함에 자동 생성 후 저장 처리한다.
- 첨부파일이 필요한 경우 첨부파일 확인 문구만 추가하고 직접 파일을 메일에 첨부하지는 않는다.
